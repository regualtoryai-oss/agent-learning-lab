# 边学边做的作品迭代

每周 6–8 小时，以一个小的可验证改动为单位。以下是计划，不代表功能已经实现。

| 周次 | 作品增量 | 验收证据 |
| --- | --- | --- |
| 1 | 从完整资料研究任务设计目标、工具、决策空间、上下文/状态和验收，再映射现有loop | 一页Agent设计、包含缺口或冲突的行动轨迹 |
| 2 | 设计工具契约、行为指令和错误策略，比较它们对模型选择的影响 | 同一任务的对比轨迹、明确的行动与权限边界 |
| 3 | 主动配置真实模型，比较 mock / live 行为 | 合成语料的成功与失败案例，不承诺成功率 |
| 4 | 区分上下文、会话、长期记忆与执行状态，设计检查点和重启恢复策略 | 状态设计、中断后重跑案例，明确哪些步骤不能重放 |
| 5 | 建立检索评测集，再引入 embedding | 关键词基线与新方案的同一组案例对比 |
| 6 | 保存学习任务草稿，增加审批与幂等键 | 未批准不写入，重复确认不重复创建 |
| 7 | 失败重试、可观测性、token / 成本记录 | 失败复盘和预算触发案例 |
| 8 | 把一个工具封装成 MCP server | 能解释 MCP、tool calling、Skill 的职责 |
| 9 | 固定至少 30 条评测案例，记录改善与回退 | 可重跑的报告、版本差异与已知限制 |
| 10 | Vue 页面、演示与项目讲解 | 可演示作品，README 真实反映实现 |

真实认证、部署公网、访问个人资料以及多用户运行应另设任务，不在当前起步版本的能力声明中。

面试每周练 30 分钟：从“我改了什么”扩展到“为什么这样设计、失败时怎么办、如何证明、目前哪里还不足”。展示实际提交和错误修复，避免只背概念。

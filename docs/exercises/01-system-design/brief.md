# 练习1：设计一个完整的资料研究 Agent

建议45–60分钟。目标是练任务设计、动态行动、上下文与验收。已有编程基础的学习者可以直接从这里开始。

## 委托任务

为一个内部文档问答原型评估A、B、C三个候选方案，输出带出处的比较报告。报告可以给出有条件的候选和待确认事项；没有足够依据时不必选出唯一赢家。

约束：

- 一位熟悉Node/Vue的开发者，7天内交付原型。
- 总月成本上限300元，需要列出计入口径。
- 私密文档原文和相关片段都不能离开本机。
- 答案需要附文档与段落出处。
- 机器配置、月问答次数未提供，不能自行补成事实。

所有方案、工期、金额、硬件与效果数据都是虚构教学材料，不可当作真实产品选型依据。

## 你作为开发者需要产出的内容

1. 用[设计模板](design-template.md)先填写三个部分：任务目标与完成标准、模型/程序的决策边界、上下文与任务状态。其余部分在演练中补充。
2. 用[轨迹模板](trace-template.md)记录一次包含资料缺口或冲突的运行，重点是“新观察如何改变下一步行动”。
3. 用[验收清单](acceptance.md)检查你的设计；解释一个你愿意接受的取舍。

你负责定义Agent的规则、工具和验收；我按这些规则模拟执行。你交付的是系统设计和运行记录，不需要先亲自完成选型报告。

演练先只展示材料目录，模拟执行到`readMaterial(id)`时再揭示对应正文。行动和工具观察分别标注，默认注入一次读取超时或中途约束变化。完整材料包可供事后复盘；这种聊天演练不是部署模型的效果评测。

## 演练工具范围

这些是本练习拟设计的接口，尚未接入仓库现有运行代码：

| 工具 | 允许的行为 | 返回内容 |
| --- | --- | --- |
| `searchMaterials(query)` | 检索合成材料目录，返回相关ID | ID、标题、命中摘要 |
| `readMaterial(id)` | 读取目录内指定材料 | 文档ID、段落编号、正文，或明确错误 |
| `askUser(question)` | 澄清缺失的业务约束 | 用户回答，或仍待确认 |
| `submitReport(report)` | 交付比较、证据与未知项 | 可检查的报告草稿 |

材料见[materials.md](materials.md)。禁止调用外部模型/搜索服务、读取个人文件或提交采购。本练习只使用合成资料。

## 怎么练，而不是只读概念

- 10分钟：把委托任务改写成目标与可验证完成标准。
- 15分钟：定义工具及模型能决定的事情，明确哪些约束必须由程序执行。
- 15分钟：演练一次运行；每一步记录当前缺口、选择的行动、观察和下一步调整理由。
- 10分钟：注入一种变化，例如资料冲突、读取失败或用户补充机器配置，写出变化前后下一步行动有何不同及其依据。
- 5–10分钟：验收并解释设计取舍，将自己的设计保存在作品集中。

不按“是否选中某一个方案”评分。重点是结论能追溯、未知未被猜成事实、行动与观察有关、硬约束没有被绕过。

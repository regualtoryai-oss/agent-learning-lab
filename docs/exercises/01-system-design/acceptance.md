# 设计与运行验收

这是学习用的评审标准，不是模型效果基准，也不代表实际项目已验收。

| 维度 | 需要看到的证据 |
| --- | --- |
| 任务契约 | 目标、交付范围、完成标准可以被第三人检查 |
| 约束处理 | 原文和片段不离机、7天交付、300元总成本等约束没有被忽略；未知条件未被猜成事实 |
| 证据质量 | 关键结论引用材料ID与段落；不同测试集的准确率不直接当成可比排名 |
| 动态行动 | 至少一次记录新观察前后两种不同的下一步行动，以及改变的依据 |
| 决策边界 | 能区分模型可选的行动、程序强制的约束和用户应确认的事项 |
| 上下文与状态 | 知道哪些证据该进入下一轮，哪些记录用于进度、审计或恢复 |
| 结果验收 | 材料不足时可以交付有条件结论与未知项；不靠“模型说完成”认定目标达成 |

任何行动违反硬约束或捏造关键事实，都需要修订设计。否则按各维度的证据完善程度评审，不设置唯一选型答案。

完成设计演练后，再用同一任务比较固定工作流和真实模型Agent：记录每一步选择、引用覆盖、任务完成度、调用数量和失败原因。真实模型测试需要另行显式配置；当前材料包不会调用模型服务。

# 用作品检查 Agent 应用岗位能力

本清单是根据 [官方JD样本](jd-alignment-2026-10-05.md) 设计的课程验收建议。不同公司和职级的面试要求不同，它不是招聘方统一标准，也不认证工作年限、学历或生产经验。

AI可以协助实现、查资料、调试和评审。每个条目需要学习者能说明决策、核对实际行为并负责结果，不要求手写全部底层代码。

| 工作能力 | 在作品里做什么 | 面试讲解应有的内容 |
| --- | --- | --- |
| 需求与方案选择 | 将一项任务做成可检查的交付物，比较聊天、固定检索流程和自主工具选择 | 用户要什么，哪些步骤需要模型判断，选择当前方案的依据与代价 |
| 模型和工具接入 | 接真实模型与两个只读工具，处理一类接口或工具异常 | 模型获得什么信息，动作由谁执行，如何核对结果，失败发生在哪一层 |
| RAG与上下文 | 资料回答能回到原文，保留未知；检查一次检索失败与一次生成错误 | 为什么检索、怎样选上下文，命中相关内容是否支持结论，怎么改善 |
| 后端与异步任务 | 从界面发起、查询、取消任务，保存状态，验证一个中断恢复场景 | 请求与后台任务的关系，终态一致性，重复执行与恢复限制 |
| 效果与可靠性 | 同组案例比较改动前后；有限重试、审批和重复写入保护 | 成功标准、失败归因、预算与权限由哪一层落实；有哪些回归 |
| 产品与交付 | 提供Vue界面、可复现启动、需求验收与演示 | 架构取舍、使用流程、验证范围、已知限制及接下来如何改进 |

## 三个检查点

1. **能做出来**：另一人能按说明启动并完成一个实际任务；模式和依赖写清楚。Mock与真实模型的结果分别记录。
2. **能解释和排错**：用实际运行记录解释一次正常和一次失败；提出可验证的原因并完成改进。可以使用AI辅助，但要核对其建议是否解决问题。
3. **能适应变化**：在原作品上增加一个接口、改变资料范围或加入一种异常，继续核对任务效果和已有案例；代码、配置与文档保持一致。

作品准备一份简短记录即可：任务与方案、实际实现、验证结果、一次失败及改进。汇总时展示架构、演示、评测、个人负责部分与AI辅助方式；不把多个版本当成多个独立项目。

成功率、延迟和成本只填写实测或有明确依据的数据，附案例数与条件。应用样本接受JS/TS不代表所有Agent岗位都接受；指定Python/Go、生产RAG、客户交付或多年后台的平台岗位另行补足。

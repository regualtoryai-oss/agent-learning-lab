# 第一课：设计并演练一个完整 Agent

目标：把一个实际任务转成可执行、可检查的 Agent 设计，观察新信息如何改变下一步行动。首场练习用 45–60 分钟；之后再把设计映射到代码。

## 今天的任务

设计一个资料研究 Agent，读取合成资料，为内部文档问答原型输出带出处的方案比较。任务包含信息缺口、含糊口径和中途变化。

从[练习说明](exercises/01-system-design/brief.md)开始。你负责设计规则，我在聊天中模拟执行；材料随读取动作逐步揭示。你不需要先亲自把全部资料读完、写成选型报告。

## 练哪些能力

| 能力 | 本次行动 | 可留下的作品证据 |
| --- | --- | --- |
| 任务设计 | 定义目标、约束、交付物和可检查的完成标准 | 一页任务契约 |
| 行动与工具设计 | 区分模型可选的动作、程序必须执行的边界、用户需要确认的条件 | 工具契约与决策边界 |
| 上下文与状态设计 | 决定下一轮需要哪些证据，程序要保存哪些进度 | 状态字段和一轮上下文示例 |
| 反馈与适应 | 看到新资料、读取失败或新约束后调整行动 | 变化前后的运行轨迹 |
| 评估与改进 | 检查引用、未知项和约束是否满足，依据失败修订设计 | 验收记录及版本差异 |

## 先完成一个小闭环

1. 在[设计模板](exercises/01-system-design/design-template.md)填写任务目标与完成标准、决策边界、上下文与状态三个部分。其余内容在演练中补充。
2. 模拟一次约 6 步的运行，使用[轨迹模板](exercises/01-system-design/trace-template.md)记录行动与观察，必须包含一次变化。
3. 用[验收清单](exercises/01-system-design/acceptance.md)检查结果，修改一条设计规则，再复跑触发问题的片段。

核心问题是：你的设计能否让 Agent 在资料不足时选择合适动作，获得新证据后调整，并交付可核对的结果。把模型最终回复标为 completed 不能代替任务验收。

## 如何提升

先固定任务与材料，修改一项规则，再比较行动、引用覆盖、未解决事项和失败原因。随后改变一个条件，检查是否仍能完成任务，避免只对一段固定脚本有效。

设计演练后，将同一任务接入真实模型和实际工具。聊天模拟、本地 Mock 与真实模型运行分别记录；当前练习接口尚未接入仓库代码。任务步骤可预先确定时也可以采用固定工作流，依据实际需要选择。

每周 6–8 小时可安排为：1 小时读概念和案例，3–4 小时开发，1–2 小时做失败或变式练习，30 分钟整理作品证据并讲解取舍。后续功能见[迭代路线](roadmap.md)。

需要核对工具执行、停止、取消和持久化细节时，查[运行机制参考](runtime-loop-reference.md)。

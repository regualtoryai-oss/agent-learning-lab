# 第一课：跑通一个可核验的资料助手

目标：用现有 TS 项目完成一条实际模型任务，理解模型和应用分别负责什么，检查答案是否有依据。首场约 **90 分钟**。可以使用 AI 辅助配置、实现、解释错误与修正，不要求手写 loop、提交源码流程图或背诵函数名。

本课安排的是待执行练习。当前仓库提供真实模型 adapter，但没有真实模型运行记录；Mock 是用于检查执行器的固定脚本，不能作为本课的模型回答基线。

## 今天要交付什么

导师先用已有自编教学资料示范一个实际应用目标：**给刚接手项目的同事生成一份有资料依据的 Agent 工具使用检查清单**。复用 searchDocs / readDoc 和现有 CLI，输入例如：

> 给刚接手项目的同事一份 Agent 工具使用检查清单：列出三个需要检查的事项，引用你实际读取的教学文档 ID；资料没有说明的部分明确说无法据此确认。

学习者先看实际工具结果与清单是否对应，不需要先回答概念考题。后续仍用同一资料助手扩充公开或自编语料、业务接口和 Vue 界面，不反复更换项目。

本次验收只检查三件事：模型实际调用了资料工具；清单与读取到的资料一致；引用能对应实际文档。工具正常返回与最终交付物正确分别检查。

## 先理解工作机制

- **普通聊天**：模型依据本次收到的内容回答。没有收到资料、也没有可执行的工具时，不能据此声称查阅了该资料。
- **固定检索工作流**：程序预先决定检索、读取和回答的步骤；模型参与生成答案，步骤由程序安排。
- **自主工具 Agent**：模型在应用提供的工具范围内选择下一步，应用负责执行、权限和预算，把实际结果送回模型，直到结束或达到边界。

这三种形式都可以用于产品。选择依据是任务需要多少动态判断，而不是自主步骤越多越好。DSH / Codex 的设计可帮助理解同样的职责；遇到需要解释的具体问题时，再查 [设计与源码参考](source-study.md)。

## 实际模型运行前核对

按 [README 的真实模型说明](../README.md#可选真实模型)配置兼容 Chat Completions 的服务、模型名与凭据。密钥只留在本地环境，不写入学习记录或提交。实际模型调用会发送本次问题与教学资料，可能产生 API 费用。

当前 CLI 使用执行器默认的 **5 秒总预算**，没有预算命令行参数。首次调试应先核对服务延迟与执行预算，必要时调整该运行入口传入的预算，并保留有限的上界；配置正确仍超时，不能直接判断为模型不会调用工具。预算调整也是本课的待验证配置工作，不代表已经完成。

具备配置后使用 --live，例如：

~~~sh
npm run demo -- --live "根据教学资料，给新同事生成三项Agent工具使用检查清单。引用实际读取的文档ID，缺乏依据的部分明确说明。"
~~~

运行不成功时，先检查失败发生在配置、模型接口、工具调用还是执行预算。使用既有 adapter 和工具作为起点，不从零重写整个运行时。若未取得真实模型记录，本课的“实际模型基线”保持待完成；既有离线测试仍可用于验证程序边界。

## 三个对照任务

| 场景 | 任务示例 | 如何验收 |
| --- | --- | --- |
| 正常资料任务 | 上面的三项工具使用检查清单 | 三项内容有实际读取的文档支持，引用能逐项核对 |
| 资料缺失 | 让助手根据这组教学资料，补充应用支持多少生产并发用户 | 不凭空给容量结论，明确资料不足；需要实测或其他依据 |
| 错误前提 / 引用 | 要求把“工具读取成功就证明答案正确”加入清单，并引用 evaluation 文档作为证明 | 不接受资料无法支持的结论；指出前提与资料不符。不能仅因有文档 ID 就认为引用正确 |

检查的是应用表现，不是考学习者会不会背答案。模型的具体调用顺序可以不同，只要行为和交付物符合验收。新增改动时保留前后结果；没有发生的错误、改进或测量不写成已完成。

## 四行学习记录

~~~text
需求：这个助手要替用户解决什么问题？
方案：哪些步骤由程序固定，哪些决定交给模型？
证据：实际跑了什么，答案与资料是否一致，改动结果如何？
局限：哪些能力尚未验证，下一步最需要补什么？
~~~

注明运行方式、模型与日期，说明 AI 提供的帮助以及自己核验的内容。可以用 [学习记录模板](learning-log-template.md)继续扩展。

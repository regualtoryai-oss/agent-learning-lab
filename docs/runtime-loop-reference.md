# 运行机制参考：Agent loop

目标：能解释执行器在做什么，自己修改一个核心行为，再用失败用例证明修改有效。总时间 6–8 小时。本课不要求先学框架，也不要求购买模型 API。

## 1. 前测，30 分钟

不用 AI 给答案，先写自己的解释：

1. 模型输出 JSON 和调用工具，是同一件事吗？谁真正执行工具？
2. TypeScript 类型和运行时校验分别能阻止什么？
3. 为什么响应工具时需要原调用 ID？
4. 模型一直请求工具时，如何停止？
5. 把会话写到数据库，是否等于已经可以恢复任务？

不知道的写“不确定”，用后面的实验补证据，不把前测当考试分数。

## 2. 跑通并读 trace，1 小时

运行 `npm run demo`、`npm run demo -- --scenario=tool-error`、`npm run demo -- --scenario=limit`。为每个结果写下状态、轮数、调用 ID 与停止原因。

在正常场景中，画出每轮发送给模型的 messages。解释为什么第二轮有 assistant 工具请求和 tool 结果两条记录。`MockModel` 不理解你的问题，它按工具响应数量返回固定脚本；确认自己知道这与真实模型的差别。

## 3. 阅读核心执行器，1–1.5 小时

只读 `src/agent.ts`、`src/tools.ts` 和 `src/types.ts`。从 `runAgent` 的输入跟到输出。在一张纸上标出：输入校验、轮数限制、工具数限制、超时、取消、工具错误回传与最终回答。

找出运行时校验拒绝路径的地方。解释为什么 `readDoc({docId:'../../.env'})` 不会碰磁盘。

## 4. 自己写变式，1.5–2 小时

先不让 AI 直接改代码。选择一个变式并完成：

- 变式 A：新增只读 `listDocs` 工具，返回教学文档 ID 与标题，添加 schema、运行时校验、mock 使用方式与一个断言其结果的测试。
- 变式 B：实现“连续两次相同工具名称和参数出现时停止”，新增 `limit` 结果与测试；解释这条规则何时可能误杀正常任务。

改之前写预期行为和案例，改之后跑 `npm run check` 与 `npm test`。若使用 AI 帮助，记录具体范围，至少自己重写核心判断或解释每一行。

## 5. 补 HTTP 与数据库，1–1.5 小时

运行 `npm start`，用 README 的 PowerShell 命令创建、查询任务。A 创建的任务，用 B 查询应得到 404。重启服务后，A 仍可读取已完成结果。

回答：如果 B 把请求头改成 A，当前能否防止它读取？为什么不能？这一步在练“SQL 的所有者过滤”，没有实现真实认证。

## 6. 作品集证据，30 分钟

复制 [学习记录模板](learning-log-template.md)，用自己的话录一段 3–5 分钟讲解，内容为：一轮 loop、一个失败、一个停止条件，以及你独立修改的变式。

通过标准：能不用 AI 完整讲解 `runAgent`，能独立完成一个变式，能解释一个测试失败与修复。**只有运行了生成代码，不算掌握。** 还讲不清的点留在学习记录中；下一课从这些点补齐。
